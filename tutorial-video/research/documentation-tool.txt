OPTIONAL EDITOR: ORDINARY SOURCE AND MATCHING DESIGN DATA

The editor is optional. Its model/generator are separate from the normal main
application build, SDK and release graph (editor/README.md:13–17).
Applications adopt only needed visual/ui or visual/flow runtime and retained
generated headers, plus the existing GUI boundary (editor/README.md:179–182).
They compile ordinary source and CMake inputs without the authoring editor.
People and AI coding agents can work directly in the repository's source/build
files and use ordinary tools; a project can ignore the optional editor entirely.

Agents can also prepare data that the editor understands:
- schema-1 UTF-8 project.json owns forms, controls, IDs, event references, flows,
  typed ports/connections and argument-array build/run recipes;
- file fields navigate to handwritten implementation, header fields include
  declaration headers, symbol fields name the explicit C++ adapter wrapper;
- generated_directory and cpp_namespace select the deterministic C++ destination;
- event wrappers receive services, Ui and typed input; flow factories return an
  owned Block and handle typed stream buffers; ordinary C/C++/Rust logic lives
  underneath, with explicit ABI calls and separate compilation rules.

This is compatibility with a documented schema and ordinary source, not automatic
import of arbitrary handwritten C++ layouts. The Files editor has no C/C++/Rust
parser; Forms edits the saved design JSON (editor/README.md:128, 152–159).
The model rejects unknown fields, unsupported versions, duplicate IDs, unsafe
paths and invalid composition. Exact ports/types and linked declarations matter.

Local review commands from the repository root, using an already built tool:
  ./build/editor-fltk/foundation-editor-tool validate --project PATH/project.json
  ./build/editor-fltk/foundation-editor-tool generate --project PATH/project.json
  ./build/editor-fltk/foundation-editor-tool check-generated --project PATH/project.json
Run them only on the adopting project's owned files. These are documented recipes
here; they were not executed against the application checkout by this investigator.
validate checks design; generate explicitly publishes the changed composition;
check-generated compares retained outputs. A source-only edit needs recompilation.

The generator is deterministic and local. Regeneration does not rewrite
handwritten handlers/processing implementations; new-source skeletons are created
only through explicit new-code actions (editor/generate/README.md:51–55).
An AI agent's design edits therefore need explicit generation before compilation
uses the new layout/wiring. Retained headers enable later builds without editor.

LOCAL WORK WHILE AN AI PROVIDER IS UNAVAILABLE

Supported, precise narration:
"The editor, source files and documentation are local. You can inspect the map,
adjust the interface, edit code, and build with your prepared tools even while
a frontier model provider is unavailable. AI coding assistants can later continue
from those same ordinary sources and compatible design data."

This follows from no AI service in the reader/generator/editor, no network needed
for the editor build with its documented installed/retained prerequisites, and
prepared-input normal application builds. A provider outage does not turn a remote
AI model into a local model. Existing compiler, toolkit/SDK bytes and required
host display/browser services still supply the project's local tools.
