HONEST CLAIM BOUNDARIES
- All tutorial examples supplied are display-free reference applications. Editor
  Preview displays form layout without running application handlers. Do not depict
  Preview as a live sample-processing GUI. Build/Run prints checked sample values;
  native host composition is possible but not the included default example route.
- Editor Forms edits JSON-defined/generated forms, and does not import handwritten
  C++ app layouts (editor/README.md:152-159). It is an authoring tool, not a parser,
  language server or restricted language; source files stay independently editable.
- Generated layouts can be presented through any supported adapter. Editor itself
  has only three host choices. Windows editor source adapters exist; native Windows
  editor execution remains pending (editor/README.md:53-55).
- Rust DSP has no Forms/events, only a flow. To show direct event-to-Rust capability,
  use the ordinary C ABI call as a clearly labeled code explanation or construct and
  validate a fresh combined project; do not imply this example already supplies it.
- Main Rust component supports native Linux x64/ARM64, Windows x64 MSVC, Emscripten.
  Main workspace deliberately allows one dependency-free Rust crate; add module files
  to existing crate (mod helper;), not a new external crate without adapting policy.
  cmake/RustComponent.cmake:143-145 tracks .rs inputs; tools/rust_build.py:335-355
  rejects added workspace members/dependencies/macros/build scripts.
- Existing Rust static ABI does not imply memory safety at arbitrary FFI boundaries.
  Caller owns live/disjoint buffers, panic aborts, no borrow survives the call.
- Computer vision is a supported kind of custom typed processing block, not a built-in
  computer-vision library or demonstrated included algorithm. Say "bring your signal
  processing or computer-vision algorithms" rather than claiming a supplied CV suite.
- "Two weeks ahead" and "one hour" are maintainer experience/estimates supplied by
  user, not measured generalized benchmarks. Present them as intended benefits
  without attributing an opinion to the team, and do not guarantee
  the same savings or that all future difficult projects have no new pain points.
- Prepared SDK retention reduces recurring supplier/network dependence, but the
  documented host requirements, supplier licenses and platform qualification remain.
